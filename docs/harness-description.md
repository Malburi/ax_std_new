# Harness 규모별 비교 분석 — 정확도 & 토큰 소비

## 1. 파이프라인 구성 (규모별 Tier)

> Tier는 기본 **Full** 고정 + 1회 확인 질문(또는 `"빠르게"`/`"심층"` override 키워드)으로 결정된다. 아래 소규모/중규모/대규모 구분은 과거 자동 점수판정 기준(폐기됨)을 규모 감각을 위해 참고용으로 남긴 것이다.

| Tier | 규모 감각 | 실행 에이전트 | 스킵 항목 |
|------|---------|------------|---------|
| **Lite** (소규모) | ~50파일 상당 | analyzer(lite/sonnet) → writer(sonnet) → ito-guide → validator → harness-eval | pattern-extractor, QA(온디맨드) |
| **Standard** (중규모) | ~중형 서비스 상당 | + analyzer(init/sonnet) + pattern-extractor(병렬) | QA(온디맨드) |
| **Full** (대규모, 기본값) | 레거시/마이그레이션 대상 | 전체 파이프라인, analyzer·writer 모두 **opus** | QA(온디맨드) |

## 2. 토큰 소비 비교

### 초기화 비용 (1회성)

| 항목 | Lite (소규모) | Standard (중규모) | Full (대규모) |
|------|-------------|----------------|------------|
| analyzer | ~15K–30K | ~40K–80K | ~100K–200K (opus) |
| writer | ~15K–25K | ~25K–45K | ~60K–120K (opus) |
| pattern-extractor | — | ~10K–20K | ~20K–35K |
| ito-guide | ~5K | ~5K | ~5K |
| validator | ~5K–10K | ~8K–15K | ~12K–20K |
| QA (온디맨드, 선택 시만) | — | ~10K–20K | ~20K–40K |
| harness-evaluator | ~5K | ~8K | ~10K–15K |
| **초기화 합계** | **~47K–77K** | **~99K–176K** | **~230K–438K** |
| Phase 4 재생성 (PARTIAL/RETRY 시) | +20K–40K | +40K–80K | +60K–150K |

### 작업별 토큰 소비 (초기화 이후)

하네스 사용 시 각 스킬이 `_workspace/index/*.json` 캐시를 활용 → 코드 재탐색 없음.

| 작업 유형 | 하네스 미사용 | 하네스 사용 (Lite) | 하네스 사용 (Standard) | 하네스 사용 (Full) |
|---------|-----------|----------------|------------------|----------------|
| 기능 위치 탐색 | ~8K–25K | ~3K–5K | ~2K–4K | ~2K–3K |
| 영향도 분석 | ~15K–50K | ~8K–15K | ~5K–10K | ~3K–6K |
| 신규 기능 개발 | ~20K–80K | ~10K–20K | ~6K–12K | ~4K–8K |
| SQL 리뷰 | ~10K–40K | ~8K–15K | ~5K–8K | ~3K–5K |
| 안전 변경 | ~25K–100K | ~12K–25K | ~8K–15K | ~5K–10K |

### 손익분기점 (BEP)

| 규모 | 초기화 비용 | 작업당 절감 | BEP |
|------|---------|----------|-----|
| 소규모 (Lite) | ~62K | ~8K/작업 | **약 8회** |
| 중규모 (Standard) | ~137K | ~20K/작업 | **약 7회** |
| 대규모 (Full) | ~334K | ~45K/작업 | **약 8회** |

> 실제 BEP는 **작업 다양성**이 높을수록 앞당겨진다 — 캐시 재사용률이 높아지기 때문.

## 4. 규모별 핵심 차별점

### 소규모 프로젝트 (Lite)

- **미사용 대비 이점**: 컨벤션 자동 문서화, 작업별 컨텍스트 재투입 비용 절감
- **한계**: pattern-extractor·QA 생략으로 경계면 검증 없음
- **권장**: 반복 작업이 8회 미만이면 미사용도 합리적

### 중규모 프로젝트 (Standard)

- **미사용 대비 이점**: call_graph + data_flow 인덱스로 영향 분석 정확도 30–40%p 향상
- **한계**: QA 경계면 비교(Boundary 1~6) 없어 SQL 고아 쿼리 미탐
- **권장**: 반복 개발·유지보수 프로젝트에서 명확하게 유리

### 대규모 프로젝트 (Full)

- **미사용 대비 이점**: 트랜잭션 경계·외부 통신·데드 코드까지 체계적 파악 → 마이그레이션/레거시 리팩터링 시 위험도 감소 효과가 압도적
- **주의**: opus 모델 사용으로 초기화 비용이 최대 ~590K 토큰(Phase 4 포함)에 달할 수 있음
- **권장**: 레거시 전환·마이그레이션·대형 SI 프로젝트에서 ROI 가장 높음

## 5. 결론

| 상황 | 권장 |
|------|------|
| 일회성 소규모 작업 | 하네스 미사용 |
| 2개월+ 유지보수 예정 소규모 | Lite (BEP 8회 이후 이득) |
| 중규모 신규 개발·유지보수 | Standard (정확도 30%p+, BEP 7회) |
| 레거시 전환·대형 SI | Full (정확도 50%p+, 토큰 비용보다 리스크 비용이 훨씬 큼) |

**핵심 트레이드오프**: 하네스는 초기화 비용이 크지만, 대화 횟수가 늘수록 **컨텍스트 재도출 비용을 제거**하고, 특히 대규모에서는 인간이 놓치기 쉬운 **경계면 불일치·데드 코드·트랜잭션 위험**을 구조적으로 잡아낸다는 점이 단순 토큰 절감 이상의 가치를 가진다.
